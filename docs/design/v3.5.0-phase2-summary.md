## 2. Component Design

### 2.1 Monitoring Observer

**Reference**: DevClaw v7.0.0-rc.7 `src/monitoring/`

**Why not copy**: DeepClaw is a research framework, not a software engineering pipeline. The metrics and alerting are domain-specific (research metrics, not build metrics).

**Module Structure**:
```
src/monitoring/
├── types.ts              # Metric types, Alert types, Observer config
├── Observer.ts           # Central observer, metrics collection
├── MetricsCollector.ts   # Per-run metrics tracking
├── AlertManager.ts       # Alert rules + threshold checking
└── index.ts              # Exports
```

**Metrics to Track** (research-domain specific):

| Metric | Type | Description |
|--------|------|-------------|
| `research_duration_ms` | Counter | Total research pipeline time |
| `agent_response_time_ms` | Gauge | Per-agent response time |
| `cache_hit_rate` | Gauge | Search cache hit ratio |
| `error_rate` | Gauge | Failed searches / total searches |
| `token_usage` | Counter | Total tokens consumed |
| `source_count` | Counter | Sources found per research |
| `phase_duration_ms` | Gauge | Time per pipeline phase |

**Alert Rules** (configurable thresholds):

| Rule | Threshold | Severity |
|------|:---------:|:--------:|
| `high_error_rate` | > 30% | warning |
| `slow_response` | > 30s per phase | warning |
| `low_cache_hit` | < 20% | info |
| `token_budget_exceeded` | > 100k tokens | critical |
| `zero_sources` | 0 sources found | critical |

**Integration Points**:
- Observer hooks into `Orchestrator.executePlan()` (research start/end)
- Observer hooks into agent dispatch (per-agent timing)
- Observer hooks into search engine (cache hit/miss)

**Design Decision**: Observer is passive — it collects metrics without blocking the pipeline. Alerts are emitted as events, not exceptions.

### 2.2 Human-in-the-Loop Approval

**Goal**: Add approval flow for critical decisions in the research pipeline.

**Module Structure**:
```
src/approval/
├── types.ts              # Approval types
├── ApprovalFlow.ts       # Approval state machine
├── ApprovalGate.ts       # Gate integration
└── index.ts              # Exports
```

**Approval Points** (where human input is needed):

| Point | Decision | Default |
|-------|----------|---------|
| Research plan | Approve research strategy before execution | Auto-approve if timeout |
| Budget threshold | Approve when token estimate > budget | Block, require explicit approval |
| Source quality | Review low-quality sources before inclusion | Auto-skip if timeout |

**Approval Flow State Machine**:
```
[pending] → [awaiting_approval] → [approved] / [rejected]
                    │
                    └── timeout → [auto_approved] / [auto_rejected]
```

**Key Design Decisions**:

| Decision | Rationale |
|----------|-----------|
| **Timeout ≠ approval** | Per DevClaw methodology: silence is not consent |
| **File-based requests** | Write approval request to `inbox/approval/`, wait for response |
| **Audit logging** | All approval decisions recorded with timestamp |
| **Gate integration** | ApprovalGate plugs into existing GateRegistry |

## 4. Interfaces

### 4.1 Observer Interface

```typescript
interface DeepClawObserver {
  // Lifecycle
  onResearchStart(pipelineId: string, topic: string): void;
  onResearchEnd(pipelineId: string, metrics: ResearchMetrics): void;
  
  // Per-agent
  onAgentStart(role: AgentRole, phase: string): void;
  onAgentEnd(role: AgentRole, duration: number, status: string): void;
  
  // Search
  onSearchResult(query: string, resultCount: number, cacheHit: boolean): void;
  
  // Metrics
  getMetrics(): DeepClawMetrics;
  getSnapshot(): MetricsSnapshot;
}
```

### 4.2 Approval Interface

```typescript
interface ApprovalFlow {
  requestApproval(request: ApprovalRequest): Promise<ApprovalResult>;
  checkStatus(requestId: string): ApprovalStatus;
  getPendingApprovals(): ApprovalRequest[];
}

interface ApprovalGate {
  check(stage: string): GateResult;
  approve(requestId: string, decision: ApprovalDecision): void;
}
```
