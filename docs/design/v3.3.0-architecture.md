## 1. Architecture Overview

### 1.1 Design Goals

v3.3.0 introduces two major capabilities on top of the v3.2.0 (OpenClaw Model Gateway) foundation:

1. **Reasoning-Driven Search** — An intelligent search loop that plans, searches, analyzes, detects blind spots, and iteratively refines queries (similar to o3's pivoting)
2. **Multi-Modal Synthesis** — Unified multi-modal processing powered by Gemini Vision, producing synthesized analysis across text, images, PDFs, tables, and charts

## 3. Core Module: Research Orchestrator

### 3.1 Research State Machine

The Research State Machine manages the full search-reasoning lifecycle:

```
                 ┌─────────┐
                 │  START  │
                 └────┬────┘
                      ▼
              ┌───────────────┐
         ┌───▶│    PLAN       │◀──────────────┐
         │    │ (formulate     │               │
         │    │  queries)      │               │
         │    └───────┬───────┘               │
         │            ▼                        │
         │    ┌───────────────┐               │
         │    │    SEARCH     │               │
         │    │ (execute       │               │
         │    │  queries)      │               │
         │    └───────┬───────┘               │
         │            ▼                        │
         │    ┌───────────────┐               │
         │    │   ANALYZE     │               │
         │    │ (cross-validate│              │
         │    │  detect gaps)  │               │
         │    └───────┬───────┘               │
         │            ▼                        │
         │    ┌───────────────┐     ┌─────────────────┐
         │    │    REFINE     │────▶│  blind spots?   │
         │    │ (improve query│     │  confidence low? │──▶ DONE
         │    │  fill gaps)   │     │  max iterations? │
         │    └───────────────┘     └─────────────────┘
         │            │
         └────────────┘ (yes, continue loop)
```

**States:**
- `PLAN` — Formulate search strategy, decompose query into sub-queries
- `SEARCH` — Execute search across configured sources
- `ANALYZE` — Cross-validate results, detect blind spots, compute confidence
- `REFINE` — Rewrite queries based on gaps, adjust strategy, decide whether to continue

**Transitions driven by:**
- Blind spot detection result (gaps found → PLAN, no gaps → DONE)
- Confidence threshold (below threshold → REFINE, above → DONE)
- Max iterations limit (reached → DONE with best-effort result)

### 3.2 Dynamic Planner

```
DynamicPlanner
├── Query Decomposer     — Break complex query into sub-queries
├── Strategy Selector    — Choose search strategy based on query type
├── Source Router        — Route sub-queries to best sources
└── Pivot Detector       — Detect when strategy change is needed
```

**Strategies:**
| Strategy | When to Use | Description |
|----------|-------------|-------------|
| `breadth-first` | Exploratory queries | Search broadly, then narrow |
| `depth-first` | Specific fact-finding | Deep dive on one angle first |
| `tree-search` | Comparative analysis | Branch to compare aspects |
| `pivot` | Results contradict expectations | Change direction mid-search |

**Pivoting Logic:**
1. Monitor search result quality and relevance
2. When results deviate from expected information gain → trigger pivot
3. Pivot = select new strategy + reformulate query

### 3.3 Cross-Validation Engine

```
CrossValidator
├── Fact Extractor       — Extract factual claims from results
├── Source Weighter      — Weight sources by credibility
├── Contradiction Finder — Find conflicting claims across sources
└── Confidence Scorer    — Compute aggregate confidence per claim
```

**Confidence Model:**
```
confidence = (num_agreeing_sources / total_sources) × source_credibility × claim_specificity
```

| Threshold | Action |
|-----------|--------|
| ≥ 0.9 | High confidence, accept claim |
| 0.6 – 0.9 | Medium confidence, flag for verification |
| < 0.6 | Low confidence, trigger additional search |

### 3.4 Blind Spot Detector

```
BlindSpotDetector
├── Completeness Checker — Check if all query aspects are covered
├── Contradiction Marker — Mark conflicting areas as blind spots
├── Depth Analyzer       — Detect shallow coverage areas
└── Gap Prioritizer      — Rank blind spots by importance
```

**Detection Heuristics:**
1. Query aspects not covered by any result → blind spot
2. Results disagree (>40% conflict) → blind spot (need resolution)
3. Single-source claims → weak coverage, potential blind spot
4. Temporal gaps (no recent data) → freshness blind spot

### 3.5 Iterative Refiner

```
IterativeRefiner
├── Query Rewriter       — Rewrite query based on feedback
├── Aspect Expander      — Add new aspects discovered during search
├── Synonym Generator     — Generate alternative phrasings
└── Feedback Aggregator  — Collect feedback from all analysis steps
```

**Refinement Cycle:**
1. Collect feedback: blind spots, low-confidence claims, contradictions
2. Rewrite queries targeting specific gaps
3. Adjust search parameters (sources, depth, filters)
4. Re-enter PLAN state with refined parameters

## 5. Extended Context Layer (P1)

### 5.1 Hierarchical Memory

```
┌─────────────────────────────────────────┐
│ L1: Working Memory (active session)     │
│     Size: ~10K tokens                   │
│     TTL: Session lifetime               │
│     Content: Current search context     │
├─────────────────────────────────────────┤
│ L2: Short-Term Memory (recent sessions) │
│     Size: ~50K tokens                   │
│     TTL: 7 days                         │
│     Content: Recent research topics     │
├─────────────────────────────────────────┤
│ L3: Long-Term Memory (persistent)       │
│     Size: ~500K tokens                  │
│     TTL: Persistent                     │
│     Content: All historical research    │
└─────────────────────────────────────────┘
```

**Eviction Policy:** LRU with importance weighting (frequently accessed = higher weight)

### 5.2 Long Context Support

- Chunking strategy: semantic boundary-aware splitting
- Incremental loading: load chunks on-demand as context window fills
- Summarization cascade: recent chunks full detail, older chunks summarized

### 5.3 Incremental Updates

- Delta computation: only send changed chunks to LLM
- Cache keyed by (session_id, chunk_hash)
- Version tracking for memory layers

## 6. Data Flow

### 6.1 Research Cycle Data Flow

```
User Query
    │
    ▼
ResearchStateMachine.start(query)
    │
    ├──▶ Planner.decompose(query) → SubQuery[]
    │         │
    │         ▼
    ├──▶ SearchCoordinator.search(subQueries) → SearchResult[]
    │         │
    │         ▼
    ├──▶ ReasoningEngine.infer(context) → InferenceResult
    │         │
    │         ├──▶ CrossValidator.validate(claims) → ValidationResult
    │         │         │
    │         │         ▼
    │         ├──▶ BlindSpotDetector.detect(state) → BlindSpot[]
    │         │         │
    │         │         ▼
    │         └──▶ Refiner.refine(gaps, feedback) → RefinedQuery[]
    │                   │
    │                   ▼ (if gaps found)
    │               Planner.decompose(refinedQueries) → loop back
    │
    └──▶ Synthesizer.synthesize(allResults) → ResearchReport
```

### 6.2 Multi-Modal Data Flow

```
Multi-Modal Input (image | pdf | table | chart)
    │
    ▼
InputClassifier.classify(input) → InputType
    │
    ├── InputType.IMAGE → GeminiVisionAdapter.analyze(image)
    ├── InputType.PDF   → PDFAnalyzer.parse(pdf)
    ├── InputType.TABLE → TableExtractor.extract(table)
    └── InputType.CHART → ChartParser.parse(chart)
    │
    ▼
MultiModalSynthesizer.synthesize(results) → MultiModalReport
    │
    ▼
SynthesisEngine.generate(report) → FinalReport
```

## 9. Technology Choices

| Decision | Choice | Rationale |
|----------|--------|-----------|
| **State Machine** | XState v5 | Industry standard, typed states, visualizable |
| **Model Provider** | OpenClaw Gateway (existing v3.2.0) | Reuse, no new LLM integration needed |
| **Vision API** | Gemini 2.5 Flash (via OpenClaw) | Best cost/quality for vision tasks; Flash = lower latency |
| **Reasoning Model** | o3-mini (via OpenClaw) | Best for multi-step reasoning chains |
| **Analysis Model** | Claude Opus 4 (via OpenClaw) | Best for nuanced analysis and synthesis |
| **Search** | Existing SearchCoordinator (v3.0.3) | Already supports multi-source, batching, streaming |
| **Memory (P1)** | SQLite + LRU cache | Local-first, zero-dependency, fast |
| **PDF Parsing** | pdf-parse (existing) | Already integrated in v3.1.0 |
| **Chart Detection** | Gemini Vision | More accurate than rule-based detection |
| **Cross-Modal Linking** | Embedding similarity + LLM | Embedding for fast matching, LLM for verification |

### Why Gemini Vision (not Claude Vision / GPT-4V):

1. **Cost**: Gemini Flash vision is ~80% cheaper than GPT-4V for image analysis
2. **Speed**: Flash latency < 1s for typical images
3. **Chart Reading**: Gemini outperforms GPT-4V on chart data extraction benchmarks
4. **Integration**: Already routed through OpenClaw Gateway, no new API key needed

### Why State Machine (not simple loop):

1. **Observability**: Each state transition is logged and traceable
2. **Testability**: States can be tested in isolation
3. **Flexibility**: New states (e.g., USER_INPUT, MULTI_MODAL) can be added without refactoring
4. **Debugging**: State history enables replay for debugging

## 12. Risk Mitigation

| Risk | Level | Mitigation |
|------|-------|------------|
| Gemini Vision API cost | Medium | Cache results; Flash model; batch when possible |
| State machine complexity | Low | XState provides visualization and formal verification |
| Cross-validation accuracy | Medium | Voting + weighted confidence; flag uncertain, don't claim certainty |
| Pivoting loop divergence | Low | Max iterations + relevance check before each pivot |
| PDF parsing failures | Medium | Fallback to raw text extraction; flag unparseable content |
