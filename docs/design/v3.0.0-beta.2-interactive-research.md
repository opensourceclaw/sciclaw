## 一、设计目标

提升 DeepClaw 的交互能力，实现用户与研究过程的实时协作。

核心目标：
1. 支持用户实时反馈和干预
2. 自适应查询优化
3. 渐进式报告构建
4. 研究过程可视化

---

## 二、功能需求

### 2.1 实时用户反馈 (Real-time User Feedback)

**需求描述**：
用户可以在研究过程中提供实时反馈，系统根据反馈调整研究方向。

**功能点**：
- 反馈输入接口：支持文本、选项、多选
- 反馈类型：肯定、否定、修改、补充、暂停
- 反馈处理：将反馈转换为研究调整

### 2.2 自适应查询优化 (Adaptive Query Optimization)

**需求描述**：
根据用户反馈和中间结果，自动调整搜索查询策略。

**功能点**：
- 查询重写：根据反馈修改查询
- 查询扩展：添加相关术语
- 查询优先级：调整多个查询的执行顺序
- 查询去重：避免重复查询

### 2.3 渐进式报告构建 (Progressive Report Building)

**需求描述**：
分阶段构建最终报告，用户可以在中间阶段审查和调整。

**功能点**：
- 章节拆分：将报告分为多个可独立完成的章节
- 增量生成：每章节独立生成
- 中间预览：用户可在生成过程中查看进度
- 章节重生成：支持单独重生成某个章节

### 2.4 研究过程可视化 (Research Process Visualization)

**需求描述**：
展示研究进度、当前状态、已完成任务。

**功能点**：
- 进度条：显示整体完成度
- 任务列表：显示正在进行和待处理的任务
- 状态展示：搜索中、分析中、写作中
- 时间统计：各阶段耗时

### 3.2 核心接口

```typescript
// 用户反馈
interface UserFeedback {
  type: "positive" | "negative" | "modify" | "supplement" | "pause";
  content: string;
  target?: string;  // 指向特定结果
  timestamp: Date;
}

interface FeedbackCollector {
  collect(): Promise<UserFeedback>;
  process(feedback: UserFeedback): ProcessedFeedback;
}

// 查询优化
interface QueryOptimizer {
  rewrite(query: string, feedback: ProcessedFeedback): string[];
  expand(queries: string[]): string[];
  schedule(queries: Query[]): Query[];
}

// 渐进式构建
interface ProgressiveBuilder {
  segment(report: ReportSpec): Section[];
  build(section: Section): Promise<SectionResult>;
  preview(): ProgressPreview;
}

// 可视化
interface ResearchProgress {
  totalTasks: number;
  completedTasks: number;
  currentTask: string;
  status: "idle" | "searching" | "analyzing" | "writing" | "done";
  timeStats: TimeStats;
}
```
