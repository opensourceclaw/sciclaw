### 2.2 Trigger Manager

**What DevClaw does**: Event/threshold/schedule triggers for automated pipeline actions.

**What DeepClaw needs**: Scheduled research triggers, event-based re-runs.

**Scope**: Minimal — DeepClaw is primarily interactive, not automated. A lightweight trigger can be useful for:
- Scheduled deep research runs (cron-based)
- Retry on failure (event-based)

**Implementation**:
```
src/trigger/
├── types.ts              # Trigger types
├── TriggerManager.ts     # Trigger registration + execution
└── index.ts
```

**Design**: Simple file-based trigger registry. No external dependencies. Trigger types: `schedule` (cron), `event` (on failure), `manual` (CLI).

### 2.3 Provider Abstraction

**What DevClaw does**: GitHub + GitLab provider abstraction.

**What DeepClaw needs**: LLM provider abstraction. DeepClaw already has multiple LLM providers (DeepSeek, Qwen, Kimi, GLM, MiniMax), but they exist as standalone classes. Need a unified interface.

**Current state**:
```
src/llm/providers/
├── deepseek.ts
├── qwen.ts
├── kimi.ts
├── glm.ts
├── minimax.ts
```

**What to add**: A `ProviderRegistry` that wraps existing providers with a unified interface, enabling dynamic provider routing.

**Implementation**:
```
src/llm/
├── ProviderRegistry.ts   # NEW: Unified provider registry
└── index.ts              # UPDATE: Add exports
```
