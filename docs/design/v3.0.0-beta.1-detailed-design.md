## 二、思维链模块 (chain_of_thought/)

### 2.1 类型定义

```typescript
// src/reasoning/chain_of_thought/types.ts

export enum DecompositionStrategy {
  BROAD = 'broad',       // 广度优先：并行探索多个方向
  DEEP = 'deep',         // 深度优先：深入单一推理路径
  BALANCED = 'balanced', // 平衡策略：默认
}

export enum StepStatus {
  PENDING = 'pending',
  RUNNING = 'running',
  COMPLETED = 'completed',
  FAILED = 'failed',
  SKIPPED = 'skipped',
}

export interface DecomposedStep {
  id: string;
  stepNumber: number;
  subQuestion: string;
  parentId?: string;
  dependencies: string[];   // 依赖的 step id 列表
  strategy: DecompositionStrategy;
  depth: number;
  status: StepStatus;
}

export interface ReasoningStepResult {
  step: DecomposedStep;
  reasoning: string;
  result: unknown;
  confidence: number;
  sources: string[];
  durationMs: number;
  error?: string;
}

export interface ReasoningChain {
  id: string;
  originalQuestion: string;
  strategy: DecompositionStrategy;
  steps: ReasoningStepResult[];
  finalResult: unknown;
  confidence: number;
  createdAt: Date;
  completedAt?: Date;
}

export interface ChainOfThoughtConfig {
  maxDepth: number;
  maxSteps: number;
  retryCount: number;
  timeoutMs: number;
}
```

### 2.2 problem_decomposer.ts — 问题分解器

**职责**: 将复杂问题拆解为有序的子问题序列

**接口**:

```typescript
export class ProblemDecomposer {
  constructor(config?: Partial<ChainOfThoughtConfig>);

  decompose(question: string, strategy?: DecompositionStrategy): DecomposedStep[];
}
```

**核心算法**:

1. **问题类型识别**：通过关键词匹配识别问题类型
   - `What/是什么` → 事实查询型（单步）
   - `Why/为什么/原因` → 因果分析型（因果链）
   - `How/如何/步骤` → 流程型（时序链）
   - `Compare/区别/对比` → 对比型（并行分支）
   - `多问题` → 分解为独立子问题

2. **策略影响**：
   - BROAD：浅层广度分解，每层最多 5 个子问题
   - DEEP：深层单一链，每层仅 1-2 个子问题
   - BALANCED：适中宽度和深度

3. **依赖关系构建**：
   - 时序链：step1 → step2 → step3
   - 对比分支：父问题 → [分支A, 分支B]（无交叉依赖）
   - 因果链：原因 → 机制 → 影响

**边界条件**：
- 空/空白问题 → 返回空数组
- 单步问题 → 返回仅含自身的数组
- 超出 maxDepth → 截断，截断步骤标记为 SKIPPED
- 无效 strategy → 降级为 BALANCED

### 2.3 step_executor.ts — 步骤执行器

**职责**: 按依赖关系执行推理步骤

**接口**:

```typescript
export class StepExecutor {
  constructor(llmEngine: LLMEngine, config?: Partial<ChainOfThoughtConfig>);

  async execute(steps: DecomposedStep[]): Promise<ReasoningStepResult[]>;
}
```

**执行流程**:

1. **构建依赖图**：从 DecomposedStep[] 构建 DAG
2. **拓扑排序**：确定执行顺序
3. **并行调度**：无依赖的步骤同时执行
4. **每步执行**：调用 LLMEngine 推理
5. **状态转换**：PENDING → RUNNING → COMPLETED/FAILED
6. **错误处理**：失败步骤重试 → 跳过 → 标记依赖

**关键设计**：
- 执行队列基于 Promise.all + 依赖追踪
- 每步超时通过 Promise.race 实现
- 相同 subQuestion 的步骤可复用缓存结果

**边界条件**：
- 空 steps → 立即返回 []
- 循环依赖 → 抛出错误
- 所有步骤失败 → 返回所有失败结果
- 部分失败 → 跳过后继依赖步骤

### 2.4 result_aggregator.ts — 结果汇总器

**职责**: 整合各步骤结果形成最终答案

**接口**:

```typescript
export class ResultAggregator {
  aggregate(results: ReasoningStepResult[], originalQuestion: string): ReasoningChain;
}
```

**聚合算法**：

1. **文本聚合**：按 stepNumber 顺序拼接步骤结果
2. **Sources 合并**：全局去重，保留来源映射
3. **置信度聚合**：`overall = Σ(step.confidence × weight_i) / Σ(weight_i)`
   - 权重按深度递减：`weight = 1 / (depth + 1)`
4. **冲突检测**：相同 parentId + 不同 result → 标记冲突

**边界条件**：
- 空结果 → 返回空 chain，confidence = 0
- 单结果 → 直接包裹
- 含失败 → finalResult 标注 "部分完成"

### 3.2 variable_extractor.ts — 变量提取器

**职责**: 从文本中提取关键变量/实体

**接口**:

```typescript
export class VariableExtractor {
  extractVariables(text: string): CausalVariable[];
}
```

**算法**：
1. 扫描因果关键词（"导致/引起/影响/取决于/because/lead to/affect"）附近的词
2. 提取名词短语作为候选变量
3. 别名合并（"AI" ↔ "Artificial Intelligence"）
4. 按出现频率排序，保留前 20 个

**边界条件**：
- 空文本 → []
- 无因果关键词 → 提取高频名词
- 变量名 > 100 字符 → 截断

### 3.3 causal_extractor.ts — 因果关系抽取器

**职责**: 判断变量间的因果关系

**接口**:

```typescript
export class CausalExtractor {
  extractRelations(text: string, variables: CausalVariable[]): CausalRelation[];
}
```

**因果模式库**（中英文）：

| 模式 | 示例 | 方向 |
|------|------|------|
| `X 导致 Y` | "污染导致疾病" | X→Y positive |
| `因为 X，Y` | "因为下雨，路滑" | X→Y positive |
| `X 抑制 Y` | "药物抑制生长" | X→Y negative |
| `X increases Y` | "Exercise increases fitness" | X→Y positive |
| `X leads to Y` | "Smoking leads to cancer" | X→Y positive |

**置信度计算**：
- `confidence = min(evidenceCount / 3, 1) × sourceDiversityFactor`
- 同一对变量存在多个关系 → 保留置信度最高的
- 自循环 → 过滤

### 3.4 graph_builder.ts — 因果图构建器

**接口**:

```typescript
export class CausalGraphBuilder {
  buildGraph(variables: CausalVariable[], relations: CausalRelation[]): CausalGraph;
  analyzeImpact(graph: CausalGraph): ImpactAnalysis;
}
```

**算法**：
- 有向图构建：变量 → 节点，关系 → 边
- BFS 路径查找：从根因（入度为 0）到最终影响（出度为 0）
- 路径强度：`Π(edge.strength)`
- 循环检测：DFS + visited 标记

### 4.2 logger.ts — 推理日志

**环形缓冲区**，最大 1000 条。支持 `log()`, `getLogs()`, `exportJSON()`。

### 4.3 confidence.ts — 置信度评估

**综合置信度算法**：

| 因子 | 公式 | 权重 |
|------|------|:----:|
| 证据数量 | `min(count / 5, 1)` | 0.3 |
| 证据一致性 | `agreeCount / totalCount` | 0.3 |
| 来源权威 | `avg(authority of sources)` | 0.2 |
| 时效性 | `recency decay factor` | 0.2 |

- 零证据 → overall = 0.1
- 全部矛盾 → consistency = 0
- 来源未知 → authority = 0.5

### 4.4 generator.ts — 解释生成器

**生成逻辑**：
1. 按步骤顺序迭代
2. 每步生成 `claim + justification + citations`
3. 置信度 ≥ 0.7 用肯定语气，< 0.7 用推测语气（"可能"、"推测"）
4. 末尾汇总所有证据来源

## 九、设计决策记录

| 决策 | 选项 | 选择 | 理由 |
|------|------|------|------|
| 执行调度 | 串行/并行 | 并行(DAG) | 无依赖步骤可并发，提升效率 |
| LLM 接口 | 直接依赖/接口 | 接口(LLMEngine) | 可测试性，与 summarization 一致 |
| 因果模式 | 仅规则/规则+LLM | 规则为主+LLM fallback | 性能优先，LLM 作为可选增强 |
| 日志存储 | 文件/内存 | 环形缓冲区 | 轻量，适合内存场景 |
| 可视化输出 | HTML/Markdown | Markdown+JSON | 无需额外依赖，与现有格式一致 |
