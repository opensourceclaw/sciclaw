### Edge Cases

- `sessionTimeoutMs` clamped to `[60000, 3600000]` (1min–1hr)
- `maxTurns` clamped to `[5, 200]`
- `adaptiveQueryMaxPerTurn` clamped to `[1, 10]`
- `queryGenerationTimeoutMs` clamped to `[100, 5000]`
- Session expires if `new Date() > expiresAt` and status is not COMPLETED
- Duplicate `UserPreference.key` → latest value wins

### Core Algorithm: `processInput`

```
Input:  sessionId, UserInput
Output: ResearchUpdate

1. Validate session exists and is ACTIVE/WAITING_USER
2. Create InteractionTurn with user input
3. Process input based on action:
   a. ACCEPT → confirm current direction, update context confidence += 0.1
   b. REJECT → mark direction as invalid, add to excludedTopics
   c. MODIFY → update current focus, record modification
   d. REFINE → narrow focus, increase depth
   e. SKIP → move to next topic, no context change
   f. REDIRECT → change topic, add new focus area
4. Update context based on action
5. Update session status:
   - If turn count >= maxTurns → COMPLETED
   - Otherwise → WAITING_USER (for next adaptive query)
6. Generate suggestions for next steps
7. Return ResearchUpdate
```

### Session Lifecycle

```
startSession() → ACTIVE
     │
     ├── processInput() → WAITING_USER (if needs more input)
     │        │
     │        └── processInput() → ... (loop)
     │
     ├── pauseSession() → PAUSED
     │        │
     │        └── resumeSession() → ACTIVE
     │
     └── endSession() → COMPLETED
```

### Context Update Logic

```typescript
function applyActionToContext(
  action: FeedbackAction,
  content: string,
  context: SessionContext,
): SessionContext {
  switch (action) {
    case FeedbackAction.ACCEPT:
      return { ...context, confidence: Math.min(context.confidence + 0.1, 1.0) };
    case FeedbackAction.REJECT:
      return {
        ...context,
        excludedTopics: [...context.excludedTopics, content],
        confidence: Math.max(context.confidence - 0.15, 0.1),
      };
    case FeedbackAction.REFINE:
      return {
        ...context,
        depth: context.depth + 1,
        focus: [...context.focus, content],
      };
    case FeedbackAction.REDIRECT:
      return {
        ...context,
        focus: [content],
        exploredTopics: [...context.exploredTopics, ...context.focus],
        confidence: 0.5, // reset confidence on redirect
      };
    default:
      return context;
  }
}
```

### Error Handling

- Session not found → throw `Error("Session not found: ${sessionId}")`
- Session expired → set status to EXPIRED, throw `Error("Session expired")`
- Max turns exceeded → set status to COMPLETED, include warning in ResearchUpdate
- Invalid mode on startSession → default to COLLABORATIVE
- Concurrent processInput calls → process sequentially (not rejected)

### Edge Cases

- Empty userId → generate anonymous ID `anon-${randomUUID().slice(0, 8)}`
- Empty topic → throw `Error("Topic is required")`
- Session paused while processing input → reject with "Session is paused"
- Rapid successive inputs → queue and process in order

### Core Algorithm: `generateQueries`

```
Input:  SessionContext, InteractionTurn[]
Output: AdaptiveQuery[] (≤ adaptiveQueryMaxPerTurn)

1. Analyze current context state:
   a. If confidence < 0.3 → generate CLARIFICATION queries
   b. If focus is empty or stale (unchanged for >3 turns) → generate DIRECTION queries
   c. If depth < 3 and confidence > 0.5 → generate DEPTH queries
   d. If confidence > 0.6 and depth ≥ 2 → generate VALIDATION queries
   e. Always generate 1 PREFERENCE query if user preferences are sparse

2. For each query type, select best template based on context:
   - CLARIFICATION: "What specifically about {focus} interests you?"
   - DIRECTION: "Should we explore {newTopic} or continue with {currentFocus}?"
   - DEPTH: "Would you like a deeper analysis of {focus}?"
   - VALIDATION: "Does this finding align with your understanding of {topic}?"
   - PREFERENCE: "Do you prefer {optionA} or {optionB} for this research?"

3. Score each candidate query:
   - Relevance to current focus: 0–40 points
   - Information gain potential: 0–30 points
   - User preference alignment: 0–20 points
   - Diversity from recent queries: 0–10 points

4. Select top N queries by score (N = adaptiveQueryMaxPerTurn)
5. Sort by priority descending
```

### Query Scoring

```typescript
function scoreQuery(
  query: AdaptiveQuery,
  context: SessionContext,
  history: InteractionTurn[],
): number {
  let score = 0;

  // Relevance: check if query relates to current focus
  const focusMatch = context.focus.some(f =>
    query.question.toLowerCase().includes(f.toLowerCase())
  );
  score += focusMatch ? 40 : 10;

  // Information gain: prioritize unexplored areas
  const isExplored = context.exploredTopics.some(t =>
    query.question.includes(t)
  );
  score += isExplored ? 5 : 30;

  // Preference alignment: match inferred user preferences
  const prefMatch = context.preferences.filter(p =>
    query.question.toLowerCase().includes(p.key.toLowerCase())
  ).length;
  score += Math.min(prefMatch * 10, 20);

  // Diversity: penalize similar recent queries
  const recentQuestions = history.slice(-3)
    .filter(t => t.systemMessage)
    .map(t => t.systemMessage!.content);
  const similarity = recentQuestions.reduce((max, q) => {
    const s = jaccardSimilarity(
      query.question.split(" "),
      q.split(" "),
    );
    return Math.max(max, s);
  }, 0);
  score += (1 - similarity) * 10;

  return score;
}
```

### Adaptation Algorithm: `adaptFromFeedback`

```
Input:  AdaptiveQuery[], QueryResponse[]
Output: AdaptiveQuery[]

1. For each response:
   a. If answer indicates rejection/skip → reduce priority of similar queries
   b. If answer indicates interest/acceptance → increase priority of related queries
   c. If answer reveals new preference → update context.preferences
2. Re-score all pending queries with updated context
3. Remove queries that are no longer relevant (score < threshold)
4. Generate replacement queries if count < adaptiveQueryMaxPerTurn
5. Return updated query list
```

### Performance Target

Acceptance criteria: query generation latency < 500ms. This is achieved by:
- Template-based generation (no LLM calls)
- In-memory scoring (no I/O)
- Limited template pool (≤ 50 templates)
- Early termination if score threshold not met

### Error Handling

- Empty history → generate queries based on context only
- All templates exhausted → reuse highest-scoring template with modified parameters
- Context with no focus → default to topic-based queries
- Query generation timeout → return whatever queries were generated within timeout

### Edge Cases

- Session at max depth → skip DEPTH queries, focus on VALIDATION
- All topics explored → suggest new related topics based on term expansion
- User rejects all suggestions → fall back to open-ended "What would you like to explore?"
- Very long focus strings (>200 chars) → truncate in query template

### Core Algorithm: `processFeedback`

```
Input:  sessionId, UserInput
Output: FeedbackResult

1. Detect action from input:
   - Keywords "yes/ok/agree/good/correct" → ACCEPT
   - Keywords "no/wrong/incorrect/bad" → REJECT
   - Keywords "change/modify/update/but" → MODIFY
   - Keywords "more/deeper/detail/elaborate" → REFINE
   - Keywords "skip/next/pass/ignore" → SKIP
   - Keywords "instead/rather/redirect/different" → REDIRECT
   - Default → ACCEPT (positive default)

2. Analyze sentiment:
   - Positive words → "positive"
   - Negative words → "negative"
   - Neither → "neutral"

3. Extract preferences from content:
   - "I prefer/like/want X" → { key: X, value: true }
   - "I don't like/want X" → { key: X, value: false }
   - "More/less X" → { key: X, value: "more"/"less" }

4. Compute context changes based on action
5. Generate follow-up suggestions
6. Return FeedbackResult
```

### Intent Detection

```typescript
function detectIntent(input: UserInput): FeedbackAction {
  const content = input.content.toLowerCase().trim();

  const patterns: Array<{ regex: RegExp; action: FeedbackAction }> = [
    { regex: /\b(skip|next|pass|ignore|move on)\b/i, action: FeedbackAction.SKIP },
    { regex: /\b(instead|rather|redirect|switch|different|change topic)\b/i, action: FeedbackAction.REDIRECT },
    { regex: /\b(more|deeper|detail|elaborate|expand|continue|further)\b/i, action: FeedbackAction.REFINE },
    { regex: /\b(change|modify|update|adjust|tweak|but|however)\b/i, action: FeedbackAction.MODIFY },
    { regex: /\b(no|wrong|incorrect|bad|disagree|not|nope)\b/i, action: FeedbackAction.REJECT },
    { regex: /\b(yes|ok|good|correct|agree|right|great|perfect)\b/i, action: FeedbackAction.ACCEPT },
  ];

  for (const { regex, action } of patterns) {
    if (regex.test(content)) return action;
  }

  return FeedbackAction.ACCEPT; // default positive
}
```

### Sentiment Analysis

```typescript
const POSITIVE_WORDS = new Set([
  "good", "great", "excellent", "yes", "like", "helpful",
  "useful", "interesting", "perfect", "thanks", "correct",
]);

const NEGATIVE_WORDS = new Set([
  "bad", "wrong", "no", "not", "incorrect", "dislike",
  "useless", "boring", "confusing", "irrelevant", "poor",
]);

function analyzeSentiment(input: UserInput): "positive" | "negative" | "neutral" {
  const words = input.content.toLowerCase().split(/\s+/);
  const positiveCount = words.filter(w => POSITIVE_WORDS.has(w)).length;
  const negativeCount = words.filter(w => NEGATIVE_WORDS.has(w)).length;

  if (positiveCount > negativeCount) return "positive";
  if (negativeCount > positiveCount) return "negative";
  return "neutral";
}
```

### Adaptation Trigger: `shouldAdapt`

```typescript
function shouldAdapt(context: SessionContext): boolean {
  // Adapt when confidence is low
  if (context.confidence < 0.4) return true;

  // Adapt when focus hasn't changed in a while
  if (context.exploredTopics.length > 5 && context.focus.length === 0) return true;

  // Adapt when too many topics excluded
  if (context.excludedTopics.length > context.exploredTopics.length) return true;

  return false;
}
```

### Error Handling

- Empty input content → treat as SKIP action
- Input content too long (>5000 chars) → truncate to first 5000 for analysis
- Unknown action type → default to ACCEPT

### Edge Cases

- Mixed sentiment signals → use majority, ties go to "neutral"
- Multiple preference extractions in one input → return all
- Input with only emoji → map common emoji to sentiment (👍 → positive, 👎 → negative)
- Empty extracted preferences → empty array, not error

### Main Interaction Loop: `processInput`

```
1. adapter.processInput(sessionId, input) → ResearchUpdate
2. feedbackHandler.processFeedback(sessionId, input) → FeedbackResult
3. If feedbackResult indicates context change needed:
   a. adapter.updateContext(sessionId, feedbackResult.contextChanges)
4. queryEngine.adaptFromFeedback(currentQueries, feedbackResult)
5. If queryEngine determines new queries needed:
   a. queryEngine.generateQueries(updatedContext, history) → new AdaptiveQuery[]
   b. Attach to ResearchUpdate.newQueries
6. Return ResearchUpdate
```

### Start Research: Combined Operation

```
1. session = adapter.startSession(topic, userId, mode)
2. initialQueries = queryEngine.generateQueries(session.context, [])
3. Return { session, initialQueries }
```

## 8. Data Flow

```
User starts research
       │
       ▼
InteractiveResearchEngine.startResearch(topic, userId)
  ├── adapter.startSession() → InteractionSession
  └── queryEngine.generateQueries() → AdaptiveQuery[]
       │
       ▼
User provides input
       │
       ▼
InteractiveResearchEngine.processInput(sessionId, input)
  ├── feedbackHandler.processFeedback() → FeedbackResult
  │     ├── detectIntent()
  │     ├── analyzeSentiment()
  │     └── extractPreferences()
  ├── adapter.processInput() → ResearchUpdate
  │     └── applyActionToContext()
  └── queryEngine.adaptFromFeedback() → updated AdaptiveQuery[]
       │
       ▼
ResearchUpdate
  ├── summary
  ├── newQueries (for next turn)
  ├── updatedContext
  └── suggestions
       │
       ▼
Loop until session COMPLETED or EXPIRED
```
