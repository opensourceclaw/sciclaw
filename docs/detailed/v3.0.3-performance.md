## 1. 现状分析

### 1.1 当前搜索架构

| 项目 | 详情 |
|------|------|
| 入口 | `src/search/index.ts` — `search(options)` 函数 |
| 引擎 | duckduckgo, google, bing（3 个） |
| 并发 | `Promise.all(engines.map(...))` — 按引擎并发 |
| 批处理 | `SearchOptimizer.batchSearch()` — 手动分批，默认 5 并发 |
| 去重 | `SearchOptimizer.deduplicatedSearch()` — In-flight 请求去重 |
| 连接 | 每请求新建 HTTP 连接（axios，无 keep-alive） |
| 延迟 | P95 ~10s（含网络超时 + 解析） |
| 指标 | 无可观测性 |

### 1.2 瓶颈分析

| 瓶颈 | 影响 | 根因 |
|------|------|------|
| 搜索源少 | 覆盖率低 | 仅 3 个引擎，无 API 聚合 |
| 串行级联 | 延迟叠加 | 引擎超时串行等待 |
| 无连接复用 | TCP 握手开销 | axios 默认无 keep-alive |
| 无流式 | 用户等待全部结果 | 必须等所有引擎返回 |
| 无指标 | 无法优化 | 缺少 P50/P95/P99 数据 |

### 1.3 目标

| 指标 | 当前 | 目标 |
|------|------|------|
| P95 延迟 | ~10s | < 3s |
| 并发源 | 3 | 50+ |
| 流式首结果 | N/A | < 500ms |
| 连接复用 | 无 | HTTP keep-alive 池 |

## 2. 架构概览

### 2.1 模块结构

```
src/search/
├── coordinator.ts    # NEW — SearchCoordinator 并发调度
├── batch.ts          # NEW — BatchQueue 请求批处理
├── pool.ts           # NEW — ConnectionPool HTTP 连接池
├── stream.ts         # NEW — SearchStream 流式结果
├── metrics.ts        # NEW — PerformanceMetrics 延迟/吞吐
├── types.ts          # NEW — 共享类型
├── optimizer.ts      # EXISTING — 保留 SearchOptimizer（去重）
├── index.ts          # MODIFIED — 导出新模块，向后兼容
└── engines/          # NEW — 搜索引擎目录
    ├── duckduckgo.ts
    ├── google.ts
    ├── bing.ts
    └── ...           # 50+ 源
```

### 2.2 实现顺序

| Order | Module | Depends On | Est. LOC |
|-------|--------|-----------|----------|
| 1 | `search/types.ts` | none | 60 |
| 2 | `search/metrics.ts` | types | 90 |
| 3 | `search/pool.ts` | types | 80 |
| 4 | `search/batch.ts` | types | 100 |
| 5 | `search/stream.ts` | types | 100 |
| 6 | `search/coordinator.ts` | pool, batch, metrics, stream | 200 |
| 7 | `search/index.ts` | coordinator | 30 |

**Total**: ~660 LOC (source) + ~500 (tests) = ~1160

### 2.3 设计原则

- **向后兼容**：`search(options)` API 签名不变
- **渐进增强**：每个模块可独立开关
- **优雅降级**：并发源不可用时不影响其他源
- **零额外依赖**：优先使用 Node.js 内置 `fetch` + `AbortController`

## 3. Module 1: SearchCoordinator

### 3.1 类型定义

```typescript
// src/search/types.ts

export interface SearchSourceConfig {
  id: string;
  name: string;
  enabled: boolean;
  priority: number;         // 1=high, 3=low
  timeoutMs: number;        // 单源超时

  };

export interface SearchTask {
  query: string;

    streaming?: boolean;

  latencyMs: number;
  error?: string;

export interface AggregatedResults {
  results: SearchResult[];
  totalSources: number;
  successfulSources: number;
  failedSources: number;
  totalLatencyMs: number;

}
```

### 3.2 接口设计

```typescript
// src/search/coordinator.ts

export class SearchCoordinator {
  private sources: Map<string, SearchSourceConfig>;
  private pool: ConnectionPool;
  private metrics: PerformanceMetrics;
  private activeTasks: Map<string, AbortController>;

  constructor(sources: SearchSourceConfig[], config?: CoordinatorConfig);

  /** Execute search across all enabled sources concurrently. */

  /** Search with streaming — emits results as they arrive. */

  /** Cancel an active search by query key. */

  /** Register a new search source at runtime. */

  /** Get registered sources. */
  getSources(): SearchSourceConfig[];

  /** Get current metrics snapshot. */
  getMetrics(): MetricsSnapshot;
}
```

### 3.3 并发调度策略

```
调度流程:
  1. 按 priority 分组 (1/2/3)
  2. 同组内并发发起 (ConnectionPool 控制实际并发数)
  3. 超时控制: AbortSignal.timeout(timeoutMs)
  4. 结果聚合: 按 weight 加权排序

并发控制:
  - 全局最大并发: pool.maxConcurrent (默认 20)
  - 单源 Rate Limit: Token Bucket 算法
  - 优先级调度: 高优先级源先分配连接
```

### 3.4 50+ 搜索源策略

不内置 50 个搜索引擎实现，而是提供**源注册机制**：

```typescript
// 内置源 (batteries-included)
const BUILTIN_SOURCES: SearchSourceConfig[] = [
  { id: "duckduckgo", priority: 1, timeoutMs: 5000, weight: 1.0 },
  { id: "google", priority: 1, timeoutMs: 5000, weight: 1.2 },
  { id: "bing", priority: 1, timeoutMs: 5000, weight: 1.0 },
  { id: "arxiv", priority: 2, timeoutMs: 8000, weight: 1.5 },
  { id: "wikipedia", priority: 1, timeoutMs: 3000, weight: 1.3 },
  { id: "github", priority: 2, timeoutMs: 5000, weight: 0.8 },
  // ... 可扩展
];

// 用户注册自定义源
coordinator.registerSource({
  id: "custom-api",
  name: "Custom Search API",
  enabled: true,
  priority: 1,
  timeoutMs: 5000,
  weight: 1.0,
});
```

源注册 + 内置适配器组合实现 50+ 并发，无需每个源单独实现。

## 4. Module 2: BatchQueue

### 4.1 类型定义

```typescript
// src/search/types.ts

export interface BatchConfig {
  maxBatchSize: number;       // 最大批量大小，默认 10
  maxWaitMs: number;          // 最大等待时间，默认 50ms
  flushOnFull: boolean;       // 达到 maxBatchSize 立即 flush，默认 true
}

export interface BatchEntry<T> {
  id: string;
  data: T;
  resolve: (result: any) => void;
  reject: (error: Error) => void;
  createdAt: number;
}
```

### 4.2 接口设计

```typescript
// src/search/batch.ts

export class BatchQueue<T, R> {
  private queue: BatchEntry<T>[] = [];
  private timer: ReturnType<typeof setTimeout> | null = null;
  private processing = false;

  constructor(
    private config: BatchConfig,
    private processor: (batch: T[]) => Promise<R[]>,
  );

  /** Enqueue a single item, returns promise that resolves when batch completes. */
  enqueue(item: T): Promise<R>;

  /** Force flush pending batch. */
  flush(): Promise<void>;

  /** Number of pending items. */
  get pending(): number;

  /** Whether currently processing. */
  get isProcessing(): boolean;
}
```

### 4.3 触发逻辑

```
enqueue(item):
  queue.push(item)
  if queue.length >= maxBatchSize && flushOnFull:
    flush()
  else if timer == null:
    timer = setTimeout(flush, maxWaitMs)

flush():
  if processing || queue.length == 0: return
  processing = true
  clearTimeout(timer); timer = null
  batch = queue.splice(0, maxBatchSize)
  results = await processor(batch.map(e => e.data))
  batch[i].resolve(results[i])  // 一一对应
  processing = false
  if queue.length > 0: schedule next flush
```

### 4.4 使用场景

批量搜索查询：多个并发研究请求共享同一个搜索接口，在 50ms 窗口内合并为单次 API 调用，减少网络往返。不适合实时要求 < 50ms 的场景。

### 5.1 类型定义

```typescript
// src/search/types.ts

export interface PoolConfig {
  maxConnections: number;       // 最大连接数，默认 50

  activeConnections: number;
  idleConnections: number;
  totalRequests: number;
  reusedConnections: number;
  connectionErrors: number;
}
```

### 5.2 接口设计

```typescript
// src/search/pool.ts

export class ConnectionPool {
  private pool: Map<string, Dispatcher[]>;  // host → connections

  constructor(private config: PoolConfig);

  /** Acquire a connection for a URL. Waits if pool is full. */
  async fetch(url: string, options?: RequestInit): Promise<Response>;

  /** Get pool statistics. */
  getStats(): PoolStats;

  /** Close all idle connections. */
  drain(): Promise<void>;

  /** Close all connections (graceful shutdown). */
  close(): Promise<void>;
}
```

### 5.3 实现策略

```
v3.0.3 方案: Node.js 内置 fetch (Node 18+) + undici Agent

import { Agent, fetch } from "undici";

const agent = new Agent({
  keepAliveTimeout: 30_000,
  keepAliveMaxTimeout: 60_000,
  connections: 50,
  pipelining: 1,
});

// 使用 agent 发起请求
const res = await fetch(url, { dispatcher: agent });

优点:
  - 零额外依赖 (Node.js 18+ 内置 undici)
  - HTTP/1.1 keep-alive 原生支持
  - 连接池自动管理

降级方案 (Node < 18):
  - 使用 http.Agent({ keepAlive: true }) 手动管理
  - 或回退到 axios + http.Agent
```

## 6. Module 4: SearchStream

### 6.1 类型定义

```typescript
// src/search/types.ts

export interface StreamEvent {
  type: "result" | "source_complete" | "error" | "complete";
  data?: SearchResult;
  sourceId?: string;
  error?: Error;
  progress?: { completed: number; total: number };
}
```

### 6.2 接口设计

```typescript
// src/search/stream.ts

export class SearchStream {
  private listeners = new Map<string, Set<Function>>();
  private cancelled = false;
  private completedSources = 0;
  private totalSources: number;

  constructor(totalSources: number);

  /** Called by coordinator when a new result arrives. */
  emit(event: StreamEvent): void;

  /** Register event handler. Returns unsubscribe function. */
  on(event: "result", cb: (result: SearchResult, sourceId: string) => void): () => void;
  on(event: "source_complete", cb: (sourceId: string, results: SearchResult[]) => void): () => void;
  on(event: "error", cb: (error: Error, sourceId: string) => void): () => void;
  on(event: "complete", cb: (stats: { total: number; latencyMs: number }) => void): () => void;

  /** Cancel the stream. */
  cancel(): void;

  /** Whether stream has been cancelled. */
  get isCancelled(): boolean;

  /** Progress 0.0–1.0. */
  get progress(): number;
}
```

### 6.3 流式数据流

```
Coordinator.searchStream(task)
  │
  ├─ source-1 ──────────► result1 ──► emit({ type: "result", data: result1, sourceId: "s1" })
  ├─ source-2 ──► result2 ──► emit({ type: "result", data: result2, sourceId: "s2" })
  ├─ source-3 ──► error ──► emit({ type: "error", error, sourceId: "s3" })
  │
  ├─ source-1 complete ──► emit({ type: "source_complete", sourceId: "s1" })
  │
  └─ all done ──► emit({ type: "complete", stats })
```

消费者逐结果处理，无需等待全部完成。首结果延迟 < 500ms。

### 7.3 百分位计算

```typescript
function percentile(sorted: number[], p: number): number {
  if (sorted.length === 0) return 0;
  const idx = Math.ceil((p / 100) * sorted.length) - 1;
  return sorted[Math.max(0, idx)]!;
}

// 在 getSnapshot() 中:
const latencies = windowRecords
  .filter(r => r.success)
  .map(r => r.latencyMs)
  .sort((a, b) => a - b);

return {
  p50: percentile(latencies, 50),
  p95: percentile(latencies, 95),
  p99: percentile(latencies, 99),
  avg: latencies.length > 0 ? latencies.reduce((s, l) => s + l, 0) / latencies.length : 0,
  // ...
};
```

## 8. 集成与数据流

### 8.1 向后兼容

```typescript
// src/search/index.ts — MODIFIED

// 原 API 保持不变
export async function search(options: SearchOptions): Promise<SearchResult[]> {
  // 内部升级为 Coordinator 调度
  const coordinator = getCoordinator();
  const results = await coordinator.search({
    query: options.query,
    sources: getDefaultSources(options.engines),
    options: { maxResults: options.maxResults },
  });
  return results.results;
}

// 新增流式 API
export function searchStream(options: SearchOptions): SearchStream {
  const coordinator = getCoordinator();
  return coordinator.searchStream({
    query: options.query,
    sources: getDefaultSources(options.engines),
    options: { maxResults: options.maxResults, streaming: true },
  });
}

// 新增指标 API
export function getSearchMetrics(): MetricsSnapshot {
  return getCoordinator().getMetrics();
}
```

### 8.2 请求生命周期

```
User: search("topic", { engines: ["duckduckgo", "google", ...] })
  │
  ▼
search() / searchStream()
  │
  ▼
SearchCoordinator.search()
  ├─ 源注册查询 → MatchSourceRegistry
  ├─ 并发调度 → Promise.allSettled(sources.map(s => ...))
  │     │
  │     ├─ ConnectionPool.fetch(url, opts)  ← TCP 复用
  │     ├─ BatchQueue.enqueue(item)         ← 批量合并
  │     └─ AbortSignal.timeout(timeoutMs)   ← 超时控制
  │
  ├─ 结果聚合 → sort + dedup (SearchOptimizer)
  │
  └─ Metrics.record(sourceId, query, latency, success)
  │
  ▼
AggregatedResults / StreamEvent[]
```

### 8.3 与现有模块的关系

| 现有模块 | 处理方式 |
|---------|---------|
| `SearchOptimizer` | 保留。Coordinator 内部调用 `deduplicatedSearch()` |
| `getCache()` | 保留。Coordinator 调用 `cache.get()` 检查缓存 |
| `search()` | 保留签名。内部委托给 Coordinator |
| `searchWithEngine()` | 迁移到 `src/search/engines/*.ts` |

## 10. 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 50+ 并发触发 Rate Limit | 高 | 中 | Token Bucket + 优先级调度，默认 20 并发 |
| undici 在 Node 18- 不可用 | 低 | 中 | http.Agent 降级方案 |
| 连接池占满内存 | 低 | 中 | maxConnections 限制 + idleTimeout 回收 |
| BatchQueue 延迟影响实时体验 | 低 | 低 | maxWaitMs 50ms 默认保证低延迟 |
| 流式 API 与现有同步代码不兼容 | 低 | 高 | 保留同步 `search()` API，`searchStream()` 为独立新增 |
