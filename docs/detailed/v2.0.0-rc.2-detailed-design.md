## 3. Module 2: Claim Extractor (`src/validation/claim_extractor.ts`)

### Exports

```typescript
export class ClaimExtractor {
  constructor()
  extractClaims(text: string, sourceUrl?: string, sourceTitle?: string): Claim[]
  extractNumericClaims(text: string): NumericClaim[]
  getStatistics(claims: Claim[]): ClaimStatistics
}

export function extractClaims(text: string, sourceUrl?: string, sourceTitle?: string): Claim[]
export function extractNumericClaims(text: string): NumericClaim[]
```

### Algorithm

**Sentence splitting** — regex split on sentence boundaries:

```typescript
const SENTENCE_SPLIT = /(?<=[.!?。！？\n])\s+/;
```

**Claim classification** — 6 detectors with scoring:

| Type | Detection Strategy | Score Formula |
|------|-------------------|---------------|
| **FACTUAL** | 15 indicator patterns: `is/are/was/were`, `according to`, `research shows`, `found that`, `in fact` | `0.4 + count × 0.1` (max 0.85) |
| **NUMERIC** | 6 patterns: `%`, `million/billion`, currencies, units (kg/km/°C), `1,234`, `123` | `0.7` if digits found |
| **QUOTATION** | 4 patterns: `"..."`, `'...'`, curly quotes | `0.85` |
| **COMPARISON** | 6 patterns: `more/less than`, `higher/lower than`, `compared to`, `as X as`, `increased by`, `up/down X%` | `0.5 + count × 0.15` (max 0.9) |
| **CAUSATION** | 5 patterns: `causes/caused by`, `because of`, `therefore`, `if...then`, `contributes to` | `0.5 + count × 0.15` (max 0.9) |
| **OPINION** | 5 patterns: `I think`, `probably`, `might be`, `arguably`, `best/worst` | `0.4 + count × 0.1` (max 0.85) |

**Numeric extraction** — first match wins, returns `NumericClaim`:

```typescript
function detectUnit(text: string): string {
  // Maps "%"→"percentage", "million"→"count", "kg"→"kg", "USD"→"USD", etc.
  // ~25 unit mappings total
}
```

**Date extraction** — 6 patterns: ISO dates, US dates, EU dates, Month Day Year, Day Month Year, Year-only.

**Confidence assignment**:
- Single-type match → `confidence = score`
- Multi-type match → highest score wins
- No match → `FACTUAL` with `confidence: 0.3`

### Error Handling

- Empty/null text → return `[]`
- Text < 10 chars → skip sentence
- Regex failure → gracefully degrade, return empty per-type
- `extractNumericClaims` returns `[]` if no numeric patterns match

### Edge Cases

- Very long text (>100KB): sentence-based extraction naturally limits per-sentence cost
- Nested quotes: first complete quote pair wins
- Multiple numbers in one sentence: only first `NumericClaim` extracted
- Overlapping patterns (e.g. "I think 50% growth causes inflation"): highest confidence type wins

## 4. Module 3: Source Scorer (`src/validation/source_scorer.ts`)

### Exports

```typescript
export class DomainScorer {
  scoreDomain(url: string): DomainScore
}

export class FreshnessScorer {
  scoreFreshness(pubDate?: string, modDate?: string): FreshnessScore
}

export class SourceScorer {
  constructor(weights?: { domain?: number; freshness?: number; authority?: number })
  scoreSource(url: string, pubDate?: string, authorityScore?: number): SourceScore
}

export function scoreSource(url: string, pubDate?: string): SourceScore
```

### Domain Reputation DB

~60 known domains with scores:

| Category | Example Domains | Score Range |
|----------|----------------|-------------|
| Academic | arxiv.org, nature.com, ieee.org | 0.85–0.95 |
| Government | who.int, nist.gov, cdc.gov | 0.85–0.95 |
| Tech/Dev | github.com, developer.mozilla.org | 0.70–0.90 |
| News | reuters.com, bbc.com, nytimes.com | 0.70–0.80 |
| Tech News | techcrunch.com, wired.com | 0.60–0.75 |
| Low Trust | medium.com, reddit.com, x.com | 0.20–0.45 |

**Domain matching** — exact match OR endsWith(`.` + known_domain), e.g. `sub.domain.com` matches `domain.com`.

**Unlisted domains**:
- Educational TLDs (`.edu`, `.ac.uk`, etc.) → `0.7`
- Government TLDs (`.gov`, `.mil`, etc.) → `0.75`
- Default unknown → `0.5`
- HTTPS → `+0.05`

### Freshness Scoring

```typescript
daysSincePublished < 30   → 1.0  ("very_recent")
daysSincePublished < 90   → 0.9  ("recent")
daysSincePublished < 180  → 0.7  ("current")
daysSincePublished < 365  → 0.5  ("acceptable")
daysSincePublished < 730  → 0.3  ("dated")
else                      → 0.1  ("outdated")
no date                   → 0.5  ("unknown")
```

**Date parsing** — 10 formats tried in order: ISO, ISO+T, ISO+TZ, `YYYY/MM/DD`, `DD Month YYYY`, `Month DD, YYYI`, `YYYY`, `MM/DD/YYYY`, `DD-MM-YYYY`, `DD.MM.YYYY`. Fallback: extract 4-digit year.

### Combined Score

```typescript
overall = domain.reputation × 0.4 + freshness.score × 0.3 + authority.score × 0.3
```

Weights validated to sum to 1.0 (throws `Error` if not).

### Error Handling

- Invalid URL → parse as raw string, score as unknown domain (`0.5`)
- Unparseable date → `freshness.score = 0.5`, `category = "unknown"`
- Missing authority → `0.5` (neutral)

| Category | Examples | Score Range |

| Research Labs | Google DeepMind, OpenAI, Microsoft Research | 0.85–0.90 |

| Other Universities | U. Toronto, NUS, U. Melbourne | 0.78–0.83 |

```typescript
overall = credentialScore × 0.25 + institutionScore × 0.30 + citationScore × 0.25 + recognitionScore × 0.20
```

**Credential score** (0.3 base):
| Keyword | Boost |
|---------|-------|
| `ph.d`, `phd`, `professor` | +0.15 |
| `research fellow`, `senior researcher` | +0.12 |
| `distinguished` | +0.10 |
| `fellow` | +0.08 |
| `m.d.` | +0.10 |

**Citation score** (0.3 base):
| Count | Score |
|-------|-------|
| ≥ 10,000 | 1.0 |
| ≥ 1,000 | 0.9 |
| ≥ 500 | 0.8 |
| ≥ 100 | 0.7 |
| ≥ 50 | 0.6 |
| ≥ 10 | 0.5 |
| ≥ 1 | 0.4 |

**Name recognition** — well-known researchers list (~40 names: Hinton, LeCun, Bengio, Ng, etc.):
- Exact match → 1.0
- Last name match → 0.5
- Unknown → 0.3

### Error Handling

- Empty author name → `score = 0.3`
- Non-numeric `citationCount` → treated as 0
- `institution` not a string → treated as unknown

## 6. Module 5: Risk Scorer (`src/validation/risk_scorer.ts`)

### Exports

```typescript
export class RiskScorer {
  constructor(weights?: { source?: number; claim?: number; verification?: number })
  assessRisk(claim: Claim, sourceScore: number, verificationScore?: number): RiskAssessment
  getRiskLevel(score: number): RiskLevel
}

export function assessRisk(claim: Claim, sourceScore: number, verificationScore?: number): RiskAssessment
```

### Claim Type Risk Mapping

| Claim Type | Risk Score | Rationale |
|-----------|-----------|-----------|
| FACTUAL | 0.1 | Easily verifiable |
| NUMERIC | 0.2 | Verifiable with data |
| QUOTATION | 0.15 | Has explicit source |
| COMPARISON | 0.3 | Context-dependent |
| CAUSATION | 0.5 | Hard to verify causality |
| OPINION | 0.7 | Subjective |

### Risk Formula

```typescript
claimTypeComponent = claimTypeRisk × 0.4 + (1 - claim.confidence) × 0.6
overallRisk = (1 - sourceScore) × 0.3 + claimTypeComponent × 0.3 + (1 - verificationScore) × 0.4
```

Note: In the formula, `sourceScore` and `verificationScore` are **inverted** (1 - score) because they represent "goodness" while risk represents "badness". Lower source quality → higher risk.

### Risk Thresholds

| Level | Threshold |
|-------|-----------|
| LOW | < 0.25 |
| MEDIUM | < 0.45 |
| HIGH | < 0.65 |
| CRITICAL | ≥ 0.65 |

### Warnings & Recommendations

Generated based on risk level, source score, and claim type:

| Condition | Warning/Recommendation |
|-----------|----------------------|
| CRITICAL | "Untrusted source detected — verify independently" |
| HIGH | "Low-quality source — cross-reference recommended" |
| sourceScore < 0.4 | "Source reliability is low (X.XX)" |
| verificationScore < 0.3 | "Claim has not been verified" |
| OPINION type | "Subjective claim — may not be factual" |
| CAUSATION type | "Causation claim — verify causal relationship" |
| No sourceUrl | "Missing source attribution" |
| HIGH/CRITICAL | "Seek confirmation from at least 2 independent sources" |
| NUMERIC type | "Verify numbers against original source data" |

### Error Handling

- `verificationScore` defaults to `0.5` when undefined
- Unknown `ClaimType` → uses `0.5` risk score
- `sourceScore` clamped to `[0, 1]`
- `claim.confidence` defaults to `0.5` if missing


**MLA 9th Edition**:
```

```


- No URL → omitted (entry ends without URL)

### Error Handling

- Missing fields use sensible defaults rather than failing
- Unknown `CitationStyle` → defaults to APA
- `noteNumber` < 1 → clamped to 1

## 9. Module 8: FactCheck Service (`src/validation/factcheck_service.ts`)

### Exports

```typescript
export class FactCheckService {
  constructor(cacheTTLMinutes?: number)
  verifyClaim(claim: Claim, referenceSources?: string[]): Promise<VerificationResult>
  verifyClaims(claims: Claim[], referenceSources?: string[]): Promise<VerificationResult[]>
  verifySource(url: string, claims: Claim[]): Promise<SourceVerificationSummary>
  clearCache(): void
  getCacheStats(): { cachedEntries: number }
}

export interface SourceVerificationSummary {
  url: string;
  totalClaims: number;
  verified: number;
  false: number;
  partiallyTrue: number;
  unverifiable: number;
  verificationRate: number;
}

export function verifyClaim(claim: Claim, referenceSources?: string[]): Promise<VerificationResult>
export function verifySource(url: string, claims: Claim[]): Promise<SourceVerificationSummary>
```

### Verification Algorithm

Since this is a reference implementation without external API integration, verification uses rule-based heuristics:

1. **Reference source cross-check**: For each reference source text, compute word overlap with claim text
2. **Word overlap** (`_textOverlap`): `|words(text1) ∩ words(text2)| / max(|words1|, |words2|)`
3. **Numeric overlap** (`_hasSimilarNumbers`): Check for common numbers between texts

### Evaluation Logic

```typescript
if (totalSources === 0):
  OPINION → UNVERIFIABLE, confidence 0.3
  else → PENDING, confidence 0.3

agreement = supporting / total
if agreement >= 0.8 && supporting >= 2: VERIFIED, confidence 0.6 + agreement * 0.3
if agreement >= 0.6: PARTIALLY_TRUE, confidence 0.5 + agreement * 0.2
if contradicting >= supporting: FALSE, confidence max(0.4, 1 - agreement)
else: PENDING, confidence 0.3
```

### Cache

- In-memory `Map<string, VerificationResult>`
- Key: MD5 hash of `claim.text + claim.type + claim.position`
- TTL: configurable (default 30 minutes), checked by comparing `checkedAt` + TTL vs `Date.now()`
- Cache eviction: passive (on lookup, expired entries skipped but not actively purged)

### Error Handling

- Empty reference sources → PENDING result
- Claim with empty text → PENDING, `confidence: 0.1`
- Cache miss → proceed with verification
- `verifySource` with empty claims array → all-zero summary

## 11. Module 10: Graph Builder (`src/knowledge/graph_builder.ts`)

### Exports

```typescript
export function buildGraph(entities: Entity[], relations: Relation[]): KnowledgeGraph
export function mergeGraphs(graphs: KnowledgeGraph[]): KnowledgeGraph
export function addToGraph(graph: KnowledgeGraph, entities: Entity[], relations: Relation[]): KnowledgeGraph
```

### Algorithm

**Entity → GraphNode**:
```typescript
function entityToNode(entity: Entity): GraphNode {
  const id = hash(entity.text);
  return {
    id,
    label: entity.text,
    type: entity.type,       // PERSON, ORG, LOC, etc.
    properties: { start: entity.start, end: entity.end },
    confidence: entity.confidence,
    sources: [],
  };
}
```

**Relation → GraphEdge**:
```typescript
function relationToEdge(relation: Relation, sourceNodeId: string, targetNodeId: string): GraphEdge {
  const id = hash(`${sourceNodeId}:${relation.type}:${targetNodeId}`);
  return {
    id,
    sourceId: sourceNodeId,
    targetId: targetNodeId,
    type: relation.type,
    label: relation.type,
    confidence: relation.confidence,
    properties: {},
    sources: [],
  };
}
```

**Adjacency list**: For each edge added, update `adjacencyList.get(sourceId).add(targetId)` and vice versa (undirected for query purposes).

**Deduplication**: Same entity text → same node ID → merged properties (higher confidence wins). Same edge signature → merged.

### Error Handling

- Empty entities array → empty graph with no nodes
- Empty relations array → graph with nodes but no edges
- Relations referencing non-existent nodes → edge not added, warning logged via `console.warn`
- Duplicate nodes → merged (higher confidence and longer sources list)

## 12. Module 11: Graph Store (`src/knowledge/graph_store.ts`)

### Exports

```typescript
export class GraphStore {
  constructor()

  getEdge(id: string): GraphEdge | undefined
  upsertNode(node: GraphNode): void
  upsertEdge(edge: GraphEdge): void
  removeNode(id: string): boolean
  removeEdge(id: string): boolean
  
  // Bulk
  importGraph(graph: KnowledgeGraph): void
  exportGraph(): KnowledgeGraph
  
  // Stats

  clear(): void
}
```

### Internal Storage

```typescript
private _nodes: Map<string, GraphNode> = new Map();
private _edges: Map<string, GraphEdge> = new Map();
private _adjacency: Map<string, Set<string>> = new Map();
```

### Graph Density Calculation

```typescript
density = (2 * edgeCount) / (nodeCount * (nodeCount - 1))
// Returns 0 for < 2 nodes
```

### Key Behaviors

- `upsertNode`: Adds or replaces node. Updates adjacency if edges reference it.
- `removeNode`: Removes node AND all edges connected to it. Updates adjacency.
- `removeEdge`: Removes single edge. Updates adjacency.
- `importGraph`: Bulk load, overwrites existing data.
- `exportGraph`: Deep copies all data.

### Error Handling

- `getNode`/`getEdge` with non-existent ID → returns `undefined` (not throw)
- `removeNode`/`removeEdge` with non-existent ID → returns `false`
- `importGraph` with null/undefined → no-op
- Graph with 0–1 nodes → `density = 0`

```typescript
  getNeighbors(nodeId: string, query?: GraphQuery): Subgraph
  findPath(fromId: string, toId: string, maxDepth?: number): GraphEdge[] | null
  querySubgraph(query: GraphQuery): Subgraph
  searchNodes(labelPattern: string): GraphNode[]
  getConnectedComponents(): GraphNode[][]
}
```

### Algorithms

**`getNeighbors`** — BFS from `nodeId`, depth 1 (direct neighbors). Filters by `query.nodeTypes`, `query.edgeTypes`, `query.minConfidence`.

```typescript
// Algorithm:
// 1. Get adjacent node IDs from adjacency list
// 2. For each neighbor, get the connecting edges
// 3. Filter by query criteria (node type, edge type, min confidence)
// 4. Return Subgraph with matching nodes and edges
```

**`findPath`** — BFS shortest path, default `maxDepth = 5`:

```typescript
// Algorithm:
// 1. Queue: [{ nodeId: fromId, path: [] }]
// 2. Visited: Set<string>
// 3. While queue not empty:
//    - Dequeue, mark visited
//    - If nodeId === toId: return path
//    - For each neighbor not visited, enqueue with path + edge
// 4. Return null if no path found within maxDepth
```

**`querySubgraph`** — Filter all nodes and edges by criteria:

```typescript
// 1. Filter nodes: node.type in query.nodeTypes (if specified), node.confidence >= query.minConfidence (if specified)
// 2. Filter edges: edge.type in query.edgeTypes (if specified), edge.confidence >= query.minConfidence (if specified)
// 3. Return Subgraph with filtered nodes and edges
```

**`searchNodes`** — Case-insensitive substring match on `node.label`:

```typescript
return allNodes.filter(n => n.label.toLowerCase().includes(labelPattern.toLowerCase()));
```

### Error Handling

- `getNeighbors` with non-existent node → empty `Subgraph`
- `findPath` with no path → returns `null`
- `findPath` from non-existent node → returns `null`
- `searchNodes` with empty pattern → returns all nodes
- `getConnectedComponents` on empty graph → `[]`
